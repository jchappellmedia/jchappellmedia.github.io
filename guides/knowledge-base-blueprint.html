The knowledge base blueprint

Most knowledge bases are organised for the person who built them. Retrieval doesn't care how tidy your folders are — it cares whether each chunk makes sense alone. That difference is why so many AI setups confidently return the wrong answer.

The core problem

When an AI searches your knowledge base, it doesn't read the whole thing. It pulls a handful of passages that look relevant and answers from those. So every passage has to survive being read completely out of context.

A heading three levels up that says "2025 Pricing" doesn't travel with the paragraph underneath it. If that paragraph just says "the rate increases to $180 after the first tier," the AI has no idea what year, what product, or what tier. It will still answer. That's the failure mode.

Rule one: every chunk carries its own context

Write so that any single paragraph, lifted out and shown to a stranger, still means something. In practice:

  • Repeat the subject instead of using "it" or "this" across a section break.
  • Put dates and versions inside the sentence, not only in the heading.
  • Restate the qualifier — "for enterprise accounts" — in each rule it applies to.

It reads slightly redundant to a human. It reads correctly to a machine. Optimise for the machine; humans skim past repetition without noticing.

Rule two: one document, one answerable question

The best unit isn't the topic — it's the question. A file called refund-policy.md is fine. A file called how-do-refunds-work-after-90-days.md is better, because it matches the shape of what someone will actually ask.

When a document tries to cover five questions, retrieval returns it for all five and the AI has to guess which part you meant. Split it.

Rule three: name files the way people ask

Filenames are high-signal for retrieval. Use the words your readers use, not your internal jargon:

✗  KB-OPS-114-v3-FINAL.md
✗  procedures/tier2/escalation.md
✓  when-to-escalate-a-support-ticket.md
✓  vendor-invoice-approval-limits-2026.md

Rule four: state facts once, link everywhere else

The moment the same number lives in two files, one of them is going stale. Pick the file that owns each fact, and have every other mention link to it rather than repeat it.

The stale-duplicate trap. When two chunks disagree, retrieval has no way to know which is current — and it may return the old one. Contradictions inside a knowledge base are worse than gaps, because a gap produces "I don't know" and a contradiction produces confident nonsense.

Rule five: date everything that can expire

Prices, policies, headcount, tooling, integrations. Put an explicit "as of" in the text itself:

As of March 2026, the standard tier is $49/month.

This gives the AI something to reason about instead of silently assuming the number is current, and it makes stale content findable later with a single search.

A structure that holds up

knowledge-base/
├── README.md              ← what's here, and what is NOT here
├── decisions/             ← why things are the way they are
├── how-to/                ← one task per file
├── reference/             ← facts, tables, limits, definitions
└── archive/               ← superseded, clearly marked

The two that get skipped and matter most: decisions, because "why" is what people actually can't reconstruct; and archive, because deleting old material loses history while leaving it in place poisons retrieval.

Testing it honestly

Write down the twenty questions people really ask. Ask them cold, in a fresh session, phrased naturally. Score each answer right, wrong, or hedged.

Then — this is the part people skip — go and read the passage it pulled from. A right answer from the wrong chunk is luck, and luck doesn't survive your next edit.

Fix the source, not the prompt. Prompt patches hide structural problems; they never remove them.

What good looks like

A knowledge base is working when new questions get correct answers without anyone touching a prompt, when you can trace every answer to one file that owns that fact, and when the fix for a wrong answer is obvious within about a minute. If any of those isn't true yet, the structure is still doing the damage — not the model.
